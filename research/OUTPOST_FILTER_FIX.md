# Target Overlay 1.0.1 据点过滤修复

输入：构建 1.8.46015.0 的既有游戏内只读采集，未读取外部游戏进程内存。

原版据点绘制路径 `18b6abe..18b6c27` 确认：管理器 `33265c0`，计数 `+c`，缓存 `+48` 步长 `2b8`，分类为缓存字节 `+2a0`；分类设置表 `32fcde0` 步长 32。`18b6b67` 比较设置 `+c`，非零时跳过原版绘制。发现状态来自网络 `+50` 步长 64、字节 `+3b`。

旧覆盖层复用了设置 `+c` 的跳过条件，导致原版隐藏的据点也无法被额外标记。落盘设置中类型 1、9、15、20 的该字节非零。类型 0 图标资源为零，其余 1..20 图标资源非零。新逻辑只排除零资源的空类型，不使用原版绘制开关判断据点身份。尚无本次异常地图的动态记录，不能把以上类型编号确定对应到用户报告的重型虫巢或追踪虫巢穴变体，也不能声称已完成实机复现。

`outpost-type-settings.bin` 为既有采集 `capture_01_module_02_0263C000.bin` 的 RVA `32fcde0` 起 672 字节，提供真实类型表夹具。测试覆盖全部 21 类型、发现撤销、同坐标支线与虫巢独立选择、坏记录隔离与场景变更拒绝。旧隐藏条件与整列表失败两种变异均被回归测试捕获。全套 47 项测试通过；新包结构、LuaJIT 语法与归档内源文件一致性验证通过。

追踪虫巢穴保留红色虫巢标记和白色支线标记，各自使用原生发现状态；两者不同步时允许分别撤销。游戏内验收仍需观察未发现的重型虫巢与追踪虫巢穴，以及自然发现后的标记撤销。
